## 次段階の具体案

1. clean な Fork 候補の上記 commit を検証対象として固定し、既存共有環境と分けて利用する方法を調査する。
2. DIALS はまず既存 3.23.0 との互換性を確認する。最新 stable や本番標準の決定は別途行う。
3. 必要な依存を明示的に有効化し、Fork の installation test を実施して全出力を保存する。
4. 第一候補の最初の 100 frames で画像読み込みと処理経路を確認する。
5. 第一候補の 3600 frames で改変前の実処理を実施し、同じ条件で再実行して再現性を測る。
6. merge 機能の改変に進む際は、第二候補の反射ファイルの整合性と入力条件を確認し、別の merge baseline を設ける。

各実行には Git commit / dirty diff、DIALS・依存 version、入力一覧と SHA-256、
全パラメータ、コマンド、スレッド数、環境有効化手順、終了コード、ログと主要出力を保存する。

baseline 完了条件案:

- 固定した Fork が実際にロードされたことを確認できる。
- 対象処理に必要な installation check が合格し、非該当チェックは理由を記録している。
- 実処理が終了し、出力が読み取れ、空の反射データなど明らかな異常がない。
- 空間群、格子定数、使用画像数、反射数、分解能、completeness、multiplicity、I/sigma、CC1/2、Rmeas を保存する。
- 同条件再実行との差を確認し、以降の比較許容幅を記録する。数値の閾値は未測定のまま設定しない。
- 過去結果との差だけで改変の影響と断定せず、version・入力・パラメータの差を確認する。
